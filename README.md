# Nexus GO Clients

This repository contains the source code for the Nexus GO clients:

- **Core Client**: Interact with the [vAudience AI Core API](https://github.com/vAudience/vaud-ai-core)
- **AigentChat Client**: Interact with the [vAudience AigentChat API](https://github.com/vAudience/aigentchat)
- **FileManager Client**: Interact with the [vAudience FileManager API](https://github.com/vAudience/vaud-ai-file-manager)

## Installation

To install the clients, execute the following commands:

```bash
go get github.com/vaudience/nexus-go-clients/core
go get github.com/vaudience/nexus-go-clients/aigentchat
go get github.com/vaudience/nexus-go-clients/filemanager
```

## Updating Clients

A client is generated from its service's committed API spec, `docs/swagger.json`, at the service's release tag, and stamped with that version:

```bash
./generateCoreClient.sh v0.22.2          # vaud-ai-core's spec at v0.22.2
./generateAigentChatClient.sh v0.53.0
./generateFileManagerClient.sh v0.25.2
```

These read the spec through `gh` (logged in) and call `generateClient.sh <part> <spec file> <version>`. That script replaces the part and tidies its module, and never commits, tags or pushes:

1. Run `./check.sh`.
2. Open a PR.
3. After the merge, tag its merge commit `<part>/v<version>`, such as `core/v0.22.2`.

A task that changes a service's API gets its client regenerated by vaudy's client threads the same way, at the service's release.

**openapi-generator 7.23.0** is required. Every part is generated with it, and the script refuses another version. If yours differs, `OPENAPI_GENERATOR="npx --yes @openapitools/openapi-generator-cli"` runs the version in `openapitools.json`, which needs Java.
