# nexus-go-clients

Go clients of the nexus services, generated by openapi-generator from each service's committed API spec. Nothing in a part is written by hand: a change goes into the service's API, then the part is generated again.

| Part | Service | Module |
|---|---|---|
| `aigentchat/` | aigentchat | `github.com/vaudience/nexus-go-clients/aigentchat` |
| `core/` | vaud-ai-core | `github.com/vaudience/nexus-go-clients/core` |
| `filemanager/` | vaud-ai-file-manager | `github.com/vaudience/nexus-go-clients/filemanager` |

Each part is a Go module of its own. The module paths use the lowercase `vaudience`.

## Generating a part

```sh
./generateClient.sh <part> <spec file> <version>
```

- **The spec** is the service's `docs/swagger.json`, at the service's release tag `v<version>`.
- **What it does:** it replaces `<part>/` with the client generated from the spec, stamped with `<version>` (`X.Y.Z`, without the `v`), and runs `go mod tidy` in it.
- **What it never does:** commit, tag or push.
- **The generator:** it needs openapi-generator 7.23.0, which every part was generated with, and refuses another version.
- **By hand:** `./generate{AigentChat,Core,FileManager}Client.sh <tag>` takes the spec at the service's tag through `gh`.

A generation that changes nothing but the stamped version changes no API: in a vaudy client thread, that ends without a PR.

## Checks

`./check.sh` runs `go vet`, `go build` and `go test` in every part.

## Releases

A person tags the merge commit of the PR that generated a part `<part>/v<version>`, with the service's version. Consumers then `go get github.com/vaudience/nexus-go-clients/<part>@v<version>`. There's no release PR.
